## 2. 일별 흐름에서 본 특징

### 2-1. 월별 규모

| 월 | 매출 | 구매 이벤트 | 세션 | 일평균 매출 |
|---|---|---|---|---|
| 2020-11 | 144,260 | 2,054 | 108,688 | 4,809 |

| 2021-01 | 57,350 | 1,204 | 118,618 | 1,850 |

- 매출 피크: 11/30(사이버먼데이), 12/9~12/16 (연말 쇼핑 시즌).
- 12/21 주부터 매출 급감 → 배송 마감 이후 시즌 종료로 보임.
- 1월 매출이 크게 낮지만, 일부는 **데이터 누락 영향**이다 (3장 참고).

### 2-2. 요일 효과가 크다

| 요일 | 일평균 세션 |
|---|---|
| 화·수 | 약 4,650 |
| 월·목·금 | 3,900 ~ 4,300 |
| 토·일 | 2,900 ~ 3,100 |

주말 세션이 평일 대비 약 30% 낮다. **전일 대비는 요일 효과 때문에 금요일→토요일마다 "급감"으로 보인다.** 일일 판단의 기본 비교는 "지난주 같은 요일 대비(WoW)"로 둬야 한다.

### 2-3. 지표별 변동성 (비교 기준과 알림 임계치 설정 근거)

| 지표 | 전일 대비 변화폭 (중앙값) | 전주 같은 요일 대비 (중앙값) | 전주 대비 상위 10% |
|---|---|---|---|
| 세션 | 12% | 11% | 33% |
| 구매 이벤트 | 32% | 35% | 108% |
| 매출 | 40% | 60% | 125% |

- 세션은 안정적이라 일 단위 ±20~30% 임계치가 의미 있다.
- **일 매출은 하루 50~160건 주문 규모라 원래 출렁임이 매우 크다.** 일 매출에 ±10% 알림을 걸면 거의 매일 알림이 뜬다.
- 결론: 매출·주문은 **최근 7일 누적(rolling 7d)** 이나 주 단위로 비교하고, 일 단위는 참고용으로 둔다.

### 2-4. 전체 퍼널 (92일 합계, 세션 기준)

| 단계 | 세션 대비 도달률 |
|---|---|
| 상품 조회 (view_item) | 21.4% |
| 장바구니 (add_to_cart) | 4.2% |
| 체크아웃 시작 (begin_checkout) | 3.1% |
| 구매 (purchase) | 1.3% |

가장 큰 이탈은 **상품 조회 → 장바구니** 구간이다.

> **주의 (추가 확인):** 11/01~11/24 중 23일은 add_to_cart 이벤트가 거의 수집되지 않았다 (체크아웃 세션은 하루 100건 이상인데 장바구니 세션은 0건). 위 92일 합계의 장바구니 도달률 4.2%는 실제보다 낮게 잡힌 값이다. 운영 BI에서는 DQ08 체크로 이 구간을 표시한다.

## 3. 데이터 품질 진단 (운영 BI 핵심 근거)

| 체크 | 결과 | 비중 | 해석 |
|---|---|---|---|
| user_pseudo_id 누락 | 0건 | 0% | 정상 |
| ga_session_id 누락 | 0건 | 0% | 정상. 세션 키 생성 가능 |
| 구매 매출 음수·0 | 0건 | 0% | 정상 |
| **구매 매출값 누락** | 450건 | 구매의 7.9% | 450건 모두 transaction_id도 없음 |
| **transaction_id 누락/(not set)** | 906건 | 구매의 15.9% | 이 중 456건은 매출은 있음 → 중복 판별 불가 |
| **같은 transaction_id 중복** | 326개 주문, 661 row | 구매의 11.6% | 아래 참고 |
| 주문 매출 ≠ 상품 매출 합계 (1% 초과) | 722건 | 매출 있는 구매의 13.8% | 매출 대사 체크 필요 |
| 상품 정보 없는 구매 | 2건 | 0.04% | 무시 가능 |

### 3-1. 주문 중복

- 중복 주문 326개 중 311개(95%)는 **같은 사용자·같은 금액**, 304개(93%)는 **10분 이내 재전송**이다. → 결제 완료 페이지 새로고침 등으로 인한 **이중 수집**으로 보인다.
- 그대로 합산하면 매출이 **22,148 (raw 매출의 6.1%) 과다 집계**된다.
- 운영 KPI의 매출은 **transaction_id 기준 중복 제거 후** 계산해야 한다.

### 3-2. 매출값 누락이 1월 말에 몰려 있다

| 주 시작일 | 구매 | 매출 누락 | 누락 비율 |
|---|---|---|---|
| 11/02 ~ 11/09 | 655 | 2 | 0~0.5% |
| 11/16 ~ 12/21 | 3,697 | 132 | 2~4% |
| 12/28 ~ 1/18 | 983 | 76 | 5~11% |
| **1/25** | **343** | **240** | **70%** |

- 1/25 주에 구매 이벤트는 343건으로 직전 주(395건)와 큰 차이가 없는데, **매출은 26,598 → 5,546으로 79% 급감**했다.
- 1/31은 구매 19건인데 매출 0이다.
- 즉, 1월 말 매출 급감은 **실제 판매 감소가 아니라 매출값 수집 누락**일 가능성이 높다.
- 기존 분석 프로젝트의 "1월 매출 하락" 해석에도 이 누락 영향이 섞여 있는지 확인이 필요하다.

> 운영 BI 관점의 의미: 매출만 보는 대시보드는 1/25 주를 "매출 폭락"으로 보고하게 된다. **"주문 수는 정상인데 매출만 급감 → 수집 이상"** 을 품질 체크가 먼저 잡아내고, AI 코멘트가 "해석 보류"를 붙이는 장면이 이 프로젝트의 핵심 데모가 될 수 있다. 일부러 오류를 주입하지 않아도 실제 데이터에 이미 사례가 있다.

## 4. 핵심 지표 후보

기존 `docs/metric_definitions.md`의 Confirmed/Candidate 지표에서 운영 리포트용으로 추렸다.

### Tier 1. 헤드라인 KPI (매일 리포트 상단, 전일·전주·전월 비교) — **확정 (2026-11-05)**

| 지표 | 계산식 | 기본 비교 단위 | 근거 |
|---|---|---|---|
| 매출 (Revenue) | SUM(purchase_revenue), **transaction_id 중복 제거** | rolling 7d vs 전주 7d | 최종 결과 지표 |
| 주문 수 (Orders) | 고유 구매 건수 (중복 제거) | rolling 7d vs 전주 7d | 매출 누락과 무관하게 거래 규모 확인 가능 |
| 세션 (Sessions) | COUNT(DISTINCT session_id) | 일 단위 WoW (같은 요일) | 안정적이라 일 단위 비교 가능 |
| 활성 사용자 (DAU / WAU) | COUNT(DISTINCT user_pseudo_id) | 일 WoW, 주 WoW | 유입 규모 |
| 세션 전환율 (Session CVR) | 구매 세션 / 전체 세션 | rolling 7d, %p 차이 | 매출 = 세션 × CVR × AOV 분해의 중간 고리 |
| 객단가 (AOV) | 매출 / 매출 있는 주문 수 | rolling 7d | 매출 누락 주문은 분모에서 제외해야 왜곡이 없음 |

매출 분해식: **매출 = 세션 × 세션 전환율 × AOV**. 일일 리포트에서 "매출이 왜 변했는지"를 세 요인으로 바로 나눠 설명할 수 있다. 주간 리포트는 기존 프로젝트의 `WAU × Weekly Buyer CVR × ARPPU`를 그대로 쓴다.

### Tier 2. 진단 지표 (헤드라인이 움직였을 때 원인 확인)

| 지표 | 계산식 | 용도 |
|---|---|---|
| 상품 조회율 | view_item 세션 / 세션 | 퍼널 1단계. 가장 큰 이탈 구간의 입구 |
| 장바구니율 | add_to_cart 세션 / view_item 세션 | 상품 조회 → 장바구니 이탈 확인 |
| 체크아웃 진입률 | begin_checkout 세션 / add_to_cart 세션 | |
| 결제 완료율 | purchase 세션 / begin_checkout 세션 | |
| 신규 사용자 비중 | first_visit 사용자 / 활성 사용자 | 유입 질 변화 |
| 기기별·국가별·매체별 매출과 CVR | 위 지표를 차원별로 | 변화가 어디서 생겼는지 위치 특정 |
| ARPPU | 매출 / 구매자 수 | 주간 분해용 |

### Tier 3. 데이터 품질 지표 (리포트 하단 배지, 실패 시 해석 보류)

| 체크 | 기준 (초안) | 등급 | EDA 근거 |
|---|---|---|---|
| 데이터 도착 | 당일 이벤트 > 0 | FAIL | |
| 세션 수 급변 | 같은 요일 대비 ±40% 초과 | WARN | 세션 WoW 상위 10%가 33% |
| 매출값 누락률 | 구매 중 매출 null > 10% | WARN, 30% 초과 시 FAIL | 평상시 2~4%, 1/25 주 70% |
| 주문 중복률 | 중복 transaction_id 비중 > 15% | WARN | 평균 11.6% |
| transaction_id 누락률 | > 20% | WARN | 평균 15.9% |
| 매출 대사 | 주문 매출 vs 상품 매출 합계 차이 > 1%인 주문 비중 > 20% | WARN | 평균 13.8% |
| **주문-매출 괴리** | 주문 수 WoW는 ±20% 이내인데 매출 WoW가 -50% 이하 | FAIL (해석 보류) | 1/25 주 사례 |

임계치는 이번 EDA의 92일 분포에서 잡은 초안이다. 2단계에서 하루치를 돌려보며 조정한다.

## 5. 비교 기준 제안

| 비교 | 정의 | 적용 지표 |
|---|---|---|
| 전일 대비 (DoD) | 어제 vs 그저께 | 리포트에 표시만, flag 판단에는 사용하지 않음 (요일 효과) |
| 전주 대비 (WoW) | 어제 vs 지난주 같은 요일 / rolling 7d vs 직전 7d | **flag 판단 기본값** |
| 전월 대비 (MoM) | 이번 달 1일~어제 누적 vs 지난달 같은 일수 누적 | 12월부터 계산 가능 (11월은 전월 데이터 없음) |

비율 지표(CVR, 퍼널 전환율)는 %가 아니라 **%p 차이**로 비교한다.
